<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| upstream `sf_19` → our tree | History, licence files and the net enter from a third party; the panel trusts our statement about them. |
| build host → vendor servers | Any fetch after the event breaks Rule 14; a "successful" `make net` can hide a failed fetch. |
| our docs → panel | A hand-typed SHA or a softened authorship claim is a repudiation risk, not a typo. |
| repo → physical media | The USB archive is the last copy if the laptop dies; an unverified copy is worse than none. |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-01-01 | Tampering | `src/nn-1a298aa575a0.nnue` substituted for a team-tuned net | high | mitigate | Pin bytes + full SHA-256 in `PROVENANCE.md`; `check_provenance.py` re-hashes the on-disk file; `export_net` + `cmp` proves the binary carries that exact net (Task 3). |
| T-01-02 | Repudiation | `Copying.txt` / `AUTHORS` drift, or a rewritten upstream header | high | mitigate | Blob comparison against `sf_19` in `scripts/check_license.sh`; the dated line goes *below* the header block, never inside it; gate exits nonzero. |
| T-01-03 | Repudiation | Provenance fields typed by hand and drifting from reality | high | mitigate | Every field has a producing command; `check_notice.py` re-derives `Base commit` from `git rev-parse` and `Bench nodes` from a literal cast of the evidence log. |
| T-01-04 | Information disclosure | A silent network fetch during a game or build | high | mitigate | Namespace build (`unshare -n`, else `-rn`) with the choice recorded in the log; assert the log contains no `Downloading from`; the net is tracked in git and hash-checked before the build. |
| T-01-05 | Tampering | Truncated history hiding the true base commit | medium | mitigate | Clone, not copy; `git merge-base --is-ancestor sf_19 HEAD` in the phase gate; full history retained (no `--depth`). |
| T-01-06 | Repudiation | USB archive incomplete or unverifiable | medium | mitigate | `archive_usb.sh` writes and re-verifies `SHA256SUMS` at the destination; refuses relative destinations and paths inside the repo. Physical hand-over is a recorded human step. |
| T-01-07 | Denial of service | Overwriting the only working binary during a rebuild | low | accept | The archived copy plus `RELEASE/SHA256SUMS` restore it; a rebuild is 3 minutes. |
| T-01-SC | Tampering | Third-party package installs (`chess` sdist) | high | mitigate | No resolver used: the sdist hash is verified before extraction, only `chess/` + `LICENSE.txt` are copied, `vendor/chess/SHA256SUMS` pins the tree, and the dependency manifest marks fastchess dev-only/unshipped. |
</threat_model>
